# 约束与能力边界

> 本文区分**开发规则**与**当前实现的真实保证**。违反规则应修复；尚未实现的保证不能靠措辞补齐。设计理由见 [DESIGN.md](./DESIGN.md)，代码行为见 [TECHNICAL.md](./TECHNICAL.md)。

## 1. 凭据与运行环境

- 密钥、Token、密码不入库；本地 `.env` 已列入 `.gitignore`。公开推送前应进行凭据扫描。
- CLI 默认不注册 `exec_command`，显式 `--allow-shell` 才开启。命令子进程过滤名称符合常见密钥模式的环境变量，但仍可读取工作区外的文件和磁盘上的凭据。**路径检查不限制 shell 的读写范围，环境变量过滤也不是凭据隔离。**
- 在没有进程隔离或明确权限门禁前，只在可信、受控的工作区试运行自主命令。不能把当前实现描述为能安全执行不可信代码的沙箱。
- CLI 从当前目录的 `.env` 加载模型配置，要求显式任务工作区并拒绝其根目录中的 `.env`；这不能发现目录树中的所有秘密文件。真实模型试运行应使用不含凭据的一次性任务目录。
- 固定测评的 shell 任务只对程序生成的一次性夹具开放命令工具，并过滤常见凭据环境变量；命令仍可访问夹具外的磁盘资源，因此它不是安全沙箱。

## 2. 当前保证及其边界

| 能力 | 当前能保证 | 当前不能保证 |
|---|---|---|
| `resolveInWorkspace` | 拒绝词法上的 `../` 越界与工作区外绝对路径 | 不解析链接、不约束命令进程 |
| 文件工具 | 访问前检查真实目标或父目录；限制文本长度；写文件默认不覆盖 | 不防并发进程在检查后替换路径；不隔离恶意代码 |
| `exec_command` | 限制 `cwd`、模型给出的超时和每个输出流的累计长度；取消时尝试终止并报告失败 | 不限制命令访问工作区外；不保证子孙进程被清理；不回滚部分写入 |
| `withTimeout` | 超时后停止等待 Promise | 不取消网络请求或其他底层操作 |
| `ToolRegistry` | `invoke` 返回文本，`invokeResult` 返回状态、文本及截断标志；可传递取消信号 | 自定义纯文本工具不能准确报告自身失败；状态不表示副作用已回滚 |

Windows 超时使用 `taskkill /t /f`，可能因系统权限失败。POSIX 当前向直接子进程发送 `SIGKILL`；经 shell 启动的后代进程可能继续运行。Node 官方文档也明确指出，杀父进程不会自动终止其子进程：[Child process 文档](https://nodejs.org/api/child_process.html#subprocesskillsignal)。因此工具返回“超时”不等于外部状态已恢复原样。

`MAX_OUTPUT_CHARS` 目前按 stdout、stderr **分别**计算，文件工具则限制内容或列表主体；状态行等文本不计入此值。不要把它当作总上下文的精确上限。

## 3. 新代码必须满足的规则

1. **明确副作用范围。** 写文件、执行命令或调用外部服务的工具应声明作用范围、失败路径及资源上限。对 shell 不能声称仅靠 `cwd` 就限制文件访问。
2. **模型能看到可恢复错误。** `registry.invoke` 返回文本，工具失败必须给出可读原因；`invokeResult` 同时给运行时明确状态。编程错误仍要在测试和运行轨迹中可定位，不能靠匹配中文提示判断成功。
3. **呈现由上层负责。** 工具可以产生其定义内的文件或进程副作用，但不直接写终端日志。`compact` / `summarize` 在注册时声明；消费它们的是未来的运行时或 UI。
4. **新增工具同时新增有意义的测试。** 覆盖正常操作、参数或 I/O 失败、越界和资源上限。涉及进程及临时文件的测试必须清理自身创建的资源。
5. **离线测试可运行。** 默认测试不依赖外网、真实 API Key 或远端服务；模型循环先用假模型验证协议与停止条件。
6. **依赖选择以维护成本为准。** 核心循环保持可理解；协议适配、取消、重试等复杂边界可以使用维护良好的 SDK。不以“零依赖”为独立目标。

代码使用 ESM、2 空格缩进，模块与函数用 `camelCase`，类用 `PascalCase`。注释应解释重要取舍和边界。

## 4. 资源预算

| 项目 | 当前默认值 | 环境变量 | 说明 |
|---|---:|---|---|
| 单条命令默认超时 | 30 秒 | `COMMAND_TIMEOUT` | 工具参数可覆盖 |
| 单条命令超时上限 | 10 分钟 | `MAX_COMMAND_TIMEOUT` | 模型参数不得突破 |
| 输出流或文件内容上限 | 8000 字符 | `MAX_OUTPUT_CHARS` | 不是完整返回字符串的上限 |
| 单次写入文本上限 | 100000 字符 | `MAX_WRITE_CHARS` | 以 JS 字符串长度计算 |
| 单次搜索文件数上限 | 2000 个 | `MAX_SEARCH_FILES` | `.git`、`node_modules` 和链接不进入扫描 |
| 单个搜索文件上限 | 1000000 字节 | `MAX_SEARCH_FILE_BYTES` | 超大文件跳过，单次读取不会超过上限加一个字节 |
| Agent 模型轮数 | 12 | `AGENT_MAX_TURNS` | 每次模型请求算一轮 |
| Agent 总耗时 | 120 秒 | `AGENT_MAX_DURATION_MS` | 模型请求可取消；工具中途取消能力因工具而异 |
| Agent 上下文字符预算 | 120000 字符 | `AGENT_MAX_CONTEXT_CHARS` | 序列化长度，不是 token 硬上限 |

CLI 的 Agent 预算配置已验证正整数；工具层配置仍采用 `parseInt(value) || default`，尚未统一严格验证。

## 5. 验收与例外

功能完成时要同时核对代码、测试和文档：文档中的“已实现”应能找到代码与证据；只写在路线图里的能力应标为计划。如果约束不适用，先说明具体场景和取舍，再更新本文，而不是在代码中悄悄绕过。
