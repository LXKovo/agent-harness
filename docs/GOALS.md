# 目标与验收

> 本文只定义目的、范围与完成标准。当前实现见 [TECHNICAL.md](./TECHNICAL.md)，设计取舍见 [DESIGN.md](./DESIGN.md)，能力边界见 [CONSTRAINTS.md](./CONSTRAINTS.md)。

## 项目目的

亲手实现一个可解释、可测试的 coding agent 基础结构，并让它在**受控工作区**完成真实的小任务。学习底层机制和完成任务同样重要；“工具能单独调用”不等于“Agent 已经可用”。

当前已实现工具层、OpenAI 兼容 Chat Completions 客户端、有界单 Agent 循环、CLI，以及九个带确定性检查器的固定任务。真实模型已完成一次手工文件任务；最早四个固定任务连续三轮取得 12/12 通过，之后新增的上下文压力、跨文件检索、沙箱与大面积探索任务各有小样本。24 模块「必须通读」任务累计 25 次运行答对 15 次，10 次失败都来自耗时或轮数预算；60 模块检索任务修复后 5/5 通过。项目仍不具备无人值守处理任意代码仓库的安全条件。

## 验收原则

1. **任务效果可复现**：给定固定任务与初始工作区，能检查最终文件、测试结果和失败原因；不只看模型的最终回答。
2. **失败可处理**：工具失败会反馈给模型；模型能调整方案，也能在无法继续时停止并说明原因。
3. **运行有边界**：总轮数、单条命令时间、输出长度和写入大小有上限。对于 shell 越界、进程残留等尚未解决的问题，必须明确标注，不能把路径检查称为完整隔离。
4. **过程可诊断**：能查看模型请求、工具调用、耗时和终止原因；从 M1 开始建立少量固定任务的评测基线。
5. **设计可解释**：新增抽象要能说明它解决的具体失败模式及其代价。

## 当前阶段：M1

已经接通一个**有界的单 Agent 工具调用循环**。模型返回结构化工具调用，运行时校验参数、执行工具、回传结果，直到模型给出最终答复或达到停止条件。经典 ReAct 的自由文本 `Thought/Action/Observation` 格式不是协议要求。

M1 完成需要同时满足：

- 已实现 OpenAI 兼容 Chat Completions 客户端；工具定义由现有 Zod schema 转换，工具调用 ID 与结果能正确关联，并已完成一次目标服务真实任务。
- 已实现最大轮数、总耗时、上下文压缩（软阈值先压缩、硬预算才终止）、模型请求取消及基本错误终止状态。内置工具的成功、拒绝、错误和截断状态已进入运行事件；自定义纯文本工具仍无法提供准确的失败状态。
- 假模型测试已覆盖读文件、写文件与结果检查；本地 HTTP 测试已跑通 CLI；真实模型已完成创建及读取确认文件的小任务。
- 已记录不含完整文件内容的运行元数据；九个固定任务覆盖文件创建、文件转换、搜索后局部修改、代码修复、超长源码定位、跨文件检索、大面积仓库探索、逐个读取大型模块的权重比对和容器隔离验证，自动保存 JSON 报告。最早四个任务的三轮基线为 12/12 通过，并记录了参数错误与测试失败后的恢复轨迹。
- CLI 默认不注册命令工具：`--docker` 在一次性容器内执行（只挂载工作区、根只读、无网络，拿不到 Docker 就拒绝执行），`--allow-shell` 在进程内直跑（仅在可信、受控环境使用）。两者互斥，不做隐式降级。

## 后续方向

会话恢复和 checkpoint 已能保存运行状态；情景记忆首版已能跨任务检索同项目记录，但历史答复尚无通用独立验收器；上下文压缩已把「一超预算就终止」改成逐级压缩：L1–L4 跳过保护窗口，只有窗口本身超过硬预算时才由 L5/L6 应急截断，真实轨迹里 L1 生效 11 次且没有让任务失败；容器沙箱首版已经能让命令在只读、无网络的一次性容器里执行，但容器共享内核，它不是虚拟机。

下一步的优先级由证据决定。24 模块「必须通读」实验累计跑了 25 次（修复保护窗口前 10 次、修复后 10 次、预算分离后 5 次）：15 次答对，10 次失败全部是耗时或轮数预算耗尽（7 次轮数、3 次耗时，且 3 次超时都在 240 秒安全网之前），没有一次是上下文超限或需要并行隔离；其中有几轮用 `search_files` 的命中/未命中逐位试探出权重，只读了 3 个文件。60 模块检索任务修复后 5/5 通过，说明「点名常量 + 精确搜索」的路径本来就不构成上下文压力。因此子 Agent 的准入条件仍不满足，下一步不是 `spawn_agent`：保护窗口的截断缺口已修复，预算也已按用例分离（轮数为主、耗时为安全网并记入报告）。夹具也已加固：审计行改为「模块名 + 300–360 位十六进制封条 + 行末 8 位十进制 weight」，去掉 `"weight":` 检索键，封条长度逐模块变化，`search_files` 既看不到权重，也无法从固定列逐位试探；正常路径变成逐个读取，但还不能断言前缀试探已完全堵死。加固后已用真实模型复测 10 次（4/10 通过，6 次失败全部是 16 轮耗尽，失败时读了 20–25 个文件，0 次 `context_limit`）；其中一次通过只用 8 次读取、却发了 26 次 `search_files`，不能排除对 8 位权重做前缀试探，需进一步确认。样本仍小，下一步是先决定「放宽轮数 / 进一步加固检索 oracle」，再进入网络搜索。子 Agent 的准入条件仍写在 [DESIGN.md](./DESIGN.md) D14。长期知识提炼、RAG 和技能仍是候选能力。

## 非目标

- 不发布通用 npm 框架，不为第三方提供稳定 API。
- 不训练或微调模型；模型调用使用现成服务或本地模型接口。
- 不实现虚拟机级或微虚拟机级隔离。当前沙箱是容器：它共享宿主内核，不能声称可以安全运行任意不可信代码。容器逃逸类漏洞、以及容器内以 root 运行带来的文件属主变化，都仍是已知边界。
- 不为了展示复杂度而提前加入多 Agent、长期记忆或完整 UI。

其他仓库（如 `min-cursor`）可提供问题案例和设计经验，但不作为本仓库的代码依赖。
