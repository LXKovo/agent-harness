# 目标与验收

> 本文只定义目的、范围与完成标准。当前实现见 [TECHNICAL.md](./TECHNICAL.md)，设计取舍见 [DESIGN.md](./DESIGN.md)，能力边界见 [CONSTRAINTS.md](./CONSTRAINTS.md)。

## 项目目的

亲手实现一个可解释、可测试的 coding agent 基础结构，并让它在**受控工作区**完成真实的小任务。学习底层机制和完成任务同样重要；“工具能单独调用”不等于“Agent 已经可用”。

当前阶段是工具层：已实现命令执行、读文件、列目录、写文件和相关测试；尚无模型接入、Agent 循环或 CLI。项目目前**不具备无人值守处理任意代码仓库的安全条件**。

## 验收原则

1. **任务效果可复现**：给定固定任务与初始工作区，能检查最终文件、测试结果和失败原因；不只看模型的最终回答。
2. **失败可处理**：工具失败会反馈给模型；模型能调整方案，也能在无法继续时停止并说明原因。
3. **运行有边界**：总轮数、单条命令时间、输出长度和写入大小有上限。对于 shell 越界、进程残留等尚未解决的问题，必须明确标注，不能把路径检查称为完整隔离。
4. **过程可诊断**：能查看模型请求、工具调用、耗时和终止原因；从 M1 开始建立少量固定任务的评测基线。
5. **设计可解释**：新增抽象要能说明它解决的具体失败模式及其代价。

## 当前范围

| 能力 | 状态 | 验收证据 |
|---|---|---|
| 工具注册、参数校验和错误回传 | 已实现 | 注册表及离线测试 |
| 文件工具的路径边界与文本长度上限 | 已实现 | 越界、链接、覆盖及截断测试 |
| 命令超时与进程终止尝试 | 已实现，能力有限 | Windows 正常权限测试；拒绝终止时返回错误；POSIX 子进程树未完整覆盖 |

| 运行记录与固定任务评测 | M1 同步建立 | 可重放的轨迹与任务结果检查 |
| 跨会话记忆、RAG、子 Agent、技能 | 候选扩展 | 由 M1 任务失败和评测结果决定优先级 |

## 下一阶段：M1

实现一个**有界的单 Agent 工具调用循环**。模型返回结构化工具调用，运行时校验参数、执行工具、回传结果，直到模型给出最终答复或达到停止条件。经典 ReAct 的自由文本 `Thought/Action/Observation` 格式不是协议要求。

M1 完成需要同时满足：

- 一个模型适配层，先支持一个已验证的模型接口；工具定义由现有 Zod schema 转换，且能正确关联工具调用 ID 与结果。
- 最大轮数、总耗时与模型请求取消；明确处理无效工具名、无效参数、工具失败和模型调用失败。
- 假模型测试能覆盖“读文件 → 修改文件 → 跑测试 → 根据结果结束或纠错”；真实模型在一次性测试工作区完成至少一个小任务。
- 每次运行保留足以定位失败的调用记录，建立一小组固定任务及检查器。评测从 M1 开始，规模可小。
- 在允许自主执行 shell 前，明确工具权限策略与运行环境。没有进程隔离时，只在可信、受控环境试运行，不宣称工作区路径检查能限制 shell。

## 后续方向

跨会话记忆、检索、子 Agent 和技能都是候选能力，不按功能清单机械推进。先用 M1 的轨迹与评测回答：缺少什么信息、哪类任务失败、能否通过更清晰的工具或提示解决。只有单 Agent 方案出现明确瓶颈时，再引入相应模块。

## 非目标

- 不发布通用 npm 框架，不为第三方提供稳定 API。
- 不训练或微调模型；模型调用使用现成服务或本地模型接口。
- 当前阶段不实现进程级沙箱，也不以此声称可以安全运行不可信命令。
- 不为了展示复杂度而提前加入多 Agent、长期记忆或完整 UI。

其他仓库（如 `min-cursor`）可提供问题案例和设计经验，但不作为本仓库的代码依赖。
